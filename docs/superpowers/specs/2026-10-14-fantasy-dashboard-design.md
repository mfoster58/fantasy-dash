# Fantasy Dashboard Design

**Date:** 2026-10-14
**League:** Husky fantasy (Sleeper league `1388299227519537152`)
**Status:** Approved design, pending implementation plan

## Goal

A shared, read-only web dashboard for one Sleeper fantasy football league, covering
all seasons in the league's history. Calmer and less busy than leagology.app.
Start minimal (standings and scoreboard) and build out in phases.

## Known facts about the league

Verified against the Sleeper API on 2026-10-14.

- Four seasons chained via `previous_league_id`: 2023, 2024, 2025 (complete), 2026 (in season, week 6).
- 10 teams. 6 playoff teams. Playoffs start week 15, one week per round, three rounds (weeks 15 to 17).
- Winners bracket has 7 games: two quarterfinals, two semifinals, a 5th place game, the championship, a 3rd place game.
- Consolation bracket has 4 games over weeks 15 and 16. It is a true toilet bowl: the lower scorer advances and the lowest scorer in the final is last place.
- Roster slots: QB, RB, RB, WR, WR, TE, FLEX, FLEX, K, DEF, plus bench (5 in 2023, 6 since 2024).
- Custom scoring, including 0.1 per completion and -0.2 per incompletion. Scoring settings are read per season and never hard-coded.
- Keeper league: max 1 keeper 2023 to 2025, max 2 in 2026. Draft picks carry `is_keeper`.
- Snake drafts, 15 rounds in 2023, 16 rounds since 2024.
- Matchup records include every rostered player's points for the week (`players_points`), starters and bench.
- Historical weekly projections and raw stats are available at `api.sleeper.app/v1/projections/nfl/regular/{season}/{week}` and `api.sleeper.app/v1/stats/nfl/regular/{season}/{week}`. Season projections at `/v1/projections/nfl/regular/{season}` include `adp_ppr`.
- Known results used as test oracles:

| Season | Champion | Runner-up | 3rd | Last place |
|---|---|---|---|---|
| 2025 | mattygggg | ErikOdd | faraz525 | vishwakn |
| 2024 | CurryLover53 | mattygggg | azhangatang | vishwakn |
| 2023 | BigBufoon | vishwakn | ErikOdd | CurryLover53 |

Note on 2024: Sleeper's consolation bracket `w` field says tarunsauce advanced in the final, but the week 16 scores (vishwakn 139.86, tarunsauce 142.52) and the commissioner's memory both say vishwakn was last. The engine therefore decides consolation outcomes from scores, not from the bracket's `w`/`l` fields.

## Architecture

Build-time data pipeline plus a static single-page app.

```
fantasy-dash/
  league.config.ts            # league id, display name, manager name overrides
  packages/
    core/                     # TypeScript, no React. Sleeper client, normalizers, stats engine.
    web/                      # Vite + React + React Router + Tailwind. Reads data/ JSON.
  data/                       # generated by sync, committed to git
    leagues.json              # season -> league id, settings summary
    players.json              # trimmed player directory (only players who ever appeared)
    seasons/2023.json ...     # one normalized + derived file per season
    history.json              # cross-season aggregates (all-time standings, h2h, honors)
  scripts/sync.ts             # fetch Sleeper -> run core -> write data/
  .github/workflows/sync.yml  # Tuesday 06:00 ET cron + manual trigger: sync, commit, deploy
  docs/superpowers/specs/
```

Tooling: pnpm workspace, TypeScript strict, Vitest, ESLint, Prettier. Deploy `packages/web/dist` to GitHub Pages.

### Why build-time

All derived stats are computed once at sync time by `core` and stored in JSON. The web app only reads and renders. This keeps the browser free of Sleeper's 5MB player file, keeps the stats engine testable as pure functions, and versions the data in git. Data freshness is weekly (Tuesday after Monday Night Football), which suits a history-focused dashboard. A client-side "live current week" mode is a possible later addition and is out of scope.

## Data model

### Identity

Managers are keyed by Sleeper `user_id`. Roster IDs and team names are per-season attributes of a manager. Co-owners are ignored; `owner_id` is the manager. `league.config.ts` may override a manager's display name.

### `players.json`

Map of `player_id` to `{ name, firstName, lastName, position, team, yearsExp }`. Includes only players who appear in any roster, matchup, or draft across all seasons. Team defenses use Sleeper's team abbreviation as the ID. Position comes from the current player file; rare historical position changes are accepted.

### `seasons/{year}.json`

```ts
interface Season {
  year: number;
  leagueId: string;
  status: 'complete' | 'in_season';
  lastScoredWeek: number;
  playoffWeekStart: number;      // 15
  rosterSlots: string[];         // starting slots only, e.g. ['QB','RB','RB','WR','WR','TE','FLEX','FLEX','K','DEF']
  scoring: Record<string, number>;
  managers: Record<userId, { userId, displayName, teamName, avatar, rosterId }>;
  weeks: Week[];                 // index = week number - 1
  brackets: { winners: BracketGame[]; consolation: BracketGame[] };
  draft: Draft;                  // arrives in Phase 4
  standings: StandingRow[];      // regular season, sorted
  honors: { champion, runnerUp, third, pointsTitle, lastPlace }; // userIds, null while in season
  // records are not stored: the web app derives them from standings via seasonRecords (packages/web/src/lib/records.ts)
}

interface Week {
  week: number;
  isPlayoff: boolean;
  games: Game[];
  highScore: userId | null;      // regular season only
}

interface Game {
  id: string;                    // `${year}-${week}-${matchupId}`
  week: number;
  tag: PlayoffTag | null;        // 'QF' | 'SF' | 'Final' | '3rd' | '5th' | 'Cons-R1' | 'Toilet Bowl'
  sides: [GameSide, GameSide];
  winner: userId | null;         // null for tie or unplayed
  margin: number;
}

interface GameSide {
  userId: string;
  points: number;
  projected: number;             // sum of starters' projections under league scoring
  ceiling: number;               // optimal lineup points
  efficiency: number;            // points / ceiling
  starters: SlotEntry[];         // in rosterSlots order
  bench: PlayerLine[];
  optimalSwaps: { out: playerId, in: playerId, gain: number }[];   // the game top 3 is derived in the web app
  recordBefore: { w, l, t };     // regular season record entering this week
  seasonPpg: number;             // regular season PPG for the season (through lastScoredWeek)
}

interface PlayerLine {
  playerId: string;
  points: number;
  projected: number | null;      // null = no projection available
  stats: Record<string, number>; // raw stat line for the box score
}
interface SlotEntry extends PlayerLine { slot: string }

interface StandingRow {
  userId; rank; w; l; t; winPct; pf; pa; ppg; maxPoints; efficiency;
  streak: string;                // 'W3' | 'L2' | '-' 
  allPlay: { w; l; t; pct };
  weeklyHighs: number;
}

interface BracketGame {
  round: number; bracket: 'winners' | 'consolation'; placement: number | null;
  week: number; home: userId | null; away: userId | null;
  homePoints: number | null; awayPoints: number | null;
  advanced: userId | null;       // decided from scores (see rules)
  gameId: string | null;
}

interface Draft {
  draftId: string; type: string; rounds: number;
  slotOrder: userId[];           // draft slot 1..N
  picks: DraftPick[];
}
interface DraftPick {
  round; pickNo; slot; userId; playerId; isKeeper: boolean;
}
// Value fields (posDraftRank, seasonPoints, posFinishRank, value, pointsOverBaseline) are added in Phase 4.
```

## Metric definitions

**Regular season** = weeks 1 through `playoffWeekStart - 1`. For an in-progress season, through `lastScoredWeek`. Standings, PF, PA, PPG, streak, all-play, weekly highs, and the points title use regular season games only.

- **Standings sort:** wins desc, then PF desc. Ties count 0.5 in Win%.
- **Max points (ceiling):** best lineup from the full roster (starters + bench) for the slots. Fill fixed position slots with the top scorers at each position, then fill FLEX from the remaining RB/WR/TE by points. Players with unknown position are ineligible.
- **Efficiency:** PF / max points. Shown as a percent. Per game and per season.
- **Optimal swaps:** the minimal set of bench-for-starter replacements that reaches the ceiling, each with the point gain.
- **STRK:** current run of consecutive W or L, formatted `W3` or `L2`. A tie resets to `-`. In all-time standings the streak continues across season boundaries.
- **All-play:** for each regular season week, one win for every other team scored below, one loss for every team scored above, one tie for equal. Summed over the season. Shown as `W-L-T` and percent.
- **Weekly high score:** the top single score in the league that week.
- **Top 3 (game):** the three highest-scoring starters across both sides.
- **Form:** `points - projected` and `points - seasonPpg`. Projected is the sum of starters' projected points, where each projection is Sleeper's weekly projected stat line multiplied by that season's scoring settings. A starter with no projection contributes 0 and is flagged; the UI says "no projection" for that player.
- **Season PPG under a manager's name in the box score:** regular season PPG for that season through `lastScoredWeek`.

**Playoff tags.** Winners bracket: round 1 = `QF`, round 2 = `SF`, round 3 with placement 1 = `Final`, placement 3 = `3rd`, placement 5 = `5th`. Consolation: round 1 = `Cons-R1`, round 2 placement 1 = `Toilet Bowl`, placement 3 = `Cons-7th`.

**Bracket resolution.** The bracket defines who played whom in which week. Outcomes are decided from the matchup scores, not Sleeper's `w`/`l` fields. In the winners bracket the higher scorer advances. In the consolation bracket the lower scorer advances. Champion and runner-up are the higher and lower scorers of the `Final`. Third is the higher scorer of the `3rd` game. Last place is the lower scorer of the `Toilet Bowl` game. If scores are tied, fall back to Sleeper's `w` field.

**Honors.** Points title = highest regular season PF. Playoff appearance = seeded into the winners bracket. Playoff wins = games won in the winners bracket, including the 3rd and 5th place games. Toilet bowls = seasons finished last.

**Head-to-head** uses every meeting including playoffs. Streak = consecutive wins by the same manager at the end of the series. Biggest win = largest margin by either side. Closest = smallest non-zero margin (or a tie if one exists).

**Draft value.** `posDraftRank` = order among same-position picks in that draft (keepers included). `posFinishRank` = rank among all NFL players at that position by season points under league scoring over weeks 1 to `lastScoredWeek`. `value = posDraftRank - posFinishRank`; positive is a steal. `pointsOverBaseline` = season points minus the points of the baseline player at the position, where baseline ranks are QB10, RB24, WR24, TE12, K10, DEF10. For an in-progress season all draft figures are labeled "to date".

## Views

Six routes behind a slim top navigation: Scores, Standings, Head-to-Head, All-Time, History, Draft. The root redirects to the current season's scoreboard. No home carousel, transactions, news, or polls.

### Phase 1

**`/standings/:season`** Season selector. Columns: Rank, Manager (avatar, team name, display name), W, L, T, Win%, PF, PA, PPG, Max, Eff%, STRK, All-Play. A divider after 6th marks the playoff line. In-progress seasons are labeled "through week N". Each column header has a tooltip with the metric definition.

**`/scores/:season/:week`** Season selector and a week strip (1 to 17 plus "Season" which stacks every week). Matchup card: both managers with avatar, team name, record entering the week, and score; efficiency chip per side; the game's top 3 starters with points and which side they belong to; a playoff round tag when applicable. Unplayed weeks show "Upcoming" with projected totals. Cards link to the box score.

**`/scores/:season/:week/:matchupId`** Box score. Header: both managers with avatar, record, season PPG, score. Lineups side by side in slot order: player, position, NFL team, compact stat line, projected, actual. Bench below, collapsed by default. Efficiency block: actual vs. ceiling per side and the optimal swaps. Form block: vs. projection and vs. season PPG per side. Footer: all-time head-to-head record between the two managers, linking to `/h2h`.

### Phase 2

**`/h2h?a=&b=`** Two manager pickers. Summary strip: series record, streak holder and length, total points each, biggest win, closest game, average margin. Below, every meeting as scoreboard cards, newest first, playoff games tagged with the round, each linking to its box score.

**`/all-time`** Standings columns across all seasons plus Titles, 2nd, 3rd, Playoff Apps, Playoff Wins, Toilet Bowls. Clicking a manager opens `/h2h` with them preselected.

### Phase 3

**`/history`** One row per season: champion, runner-up, points title, toilet bowl loser. Links to the season page. The current season shows "In progress · through week N" in place of its honors.

**`/history/:season`** Season in review: final standings table, winners and consolation brackets with scores, round 1 of the draft board (its link to `/draft/:season` is absent until Phase 4), and a Records block (most points, best PPG, best record, best all-play, most weekly highs). The Records block gets a link to a record book page when that feature exists; until then it has no link.

### Phase 4

**`/draft/:season`** Board grid: rounds as rows, draft slots as columns, snake order. Cell: player name, position with `posDraftRank` (e.g. RB7), NFL team, keeper tag. Color mode toggle: Position or Value. Value uses a diverging scale centered at 0 and clipped at about plus or minus 12 ranks. Hover or tap reveals season points, finish rank, and points over baseline. Clicking a column header highlights that manager's picks. Analysis panel: each manager's summed value and summed points over baseline with their best and worst pick; league-wide top five steals and busts.

## Visual direction

Calm and legible. Dark theme by default, light theme available, both via CSS tokens. One accent color. Tabular monospace numerals so columns align; a clean sans for names. Sleeper avatars from `sleepercdn.com`. Position colors: QB red, RB green, WR blue, TE orange, K purple, DEF gray. Dense tables with strong row hover. Mobile: cards stack, tables scroll horizontally inside their own container. The frontend-design skill guides typography and color choices during implementation.

## Sync script

`pnpm sync` (and `pnpm sync --dry-run`):

1. Read `league.config.ts`. Fetch the league, then walk `previous_league_id` until null.
2. Per season: fetch users, rosters, matchups for weeks 1 to `max(lastScoredWeek, 17)` (stop at the last week with data), winners and consolation brackets, drafts and picks. Fetch weekly projections and stats for each week and keep only players present in that week's rosters. Fetch season projections for ADP-related fields (stored but not yet displayed).
3. Fetch the player file once; trim to players referenced anywhere.
4. Run `core` to produce the season files and `history.json`.
5. Validate every output against its schema (zod). In dry-run, write to a temp directory and report. Otherwise write to `data/`.
6. Fail the whole run, leaving `data/` untouched, if any season fails to fetch or validate.

Network calls are retried three times with backoff and throttled to stay well under Sleeper's stated 1000 requests per minute.

The GitHub Action runs Tuesdays at 06:00 America/New_York and on manual dispatch. It runs sync, commits `data/` if changed, builds the web app, and deploys to GitHub Pages.

## Testing

- `core` metric functions: Vitest with a hand-built fixture league (4 teams, 3 weeks, 2-slot lineups) with expected standings, all-play, ceiling, efficiency, swaps, and streaks computed by hand.
- Bracket resolution: tests against saved real bracket and score data for 2023 to 2025, asserting the known honors table above, including the 2024 toilet bowl discrepancy.
- Draft value: fixture tests for positional ranks, keepers, and baseline math.
- Sync: schema validation tests on saved Sleeper responses (fixtures recorded once, checked into `packages/core/test/fixtures`).
- Web: render tests for tie games, bye-week zeros, an in-progress week, and a manager who left the league after one season.

## Failure handling

- Sync is all-or-nothing per run.
- Missing projection for a player: projected is `null`, contributes 0 to the team total, and the UI labels it "no projection".
- Player missing from the player file: rendered by ID, logged as a warning during sync.
- Unplayed weeks: shown as "Upcoming" with projected totals.
- In-progress season: standings and draft values labeled "through week N" / "to date"; honors null until the season completes.

## Out of scope for this spec

Live in-game scoring, transactions and waivers, power rankings, record book page, news or recaps, multi-league support, authentication, dues or polls.
